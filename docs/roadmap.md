# План развития

Приложение из проекта «Календарь звонков» перенесено целиком. Дальше оно развивается через
GitHub-процесс: каждая задача — issue, её разбирает агент в GitHub Actions, правки приходят
pull request'ом.

Задачи записаны так, как о них сообщил бы пользователь: что мешает и что он ожидает. Решение
выбирается при разборе задачи, а не заранее.

## Баги

| Issue | Кто жалуется | Суть |
|---|---|---|
| [#1](https://github.com/kirill0991/ai-for-developers-project-387/issues/1) | Владелец | В списке броней остаются встречи, которые уже прошли |
| [#2](https://github.com/kirill0991/ai-for-developers-project-387/issues/2) | Владелец, гости | На длинный тип события невозможно записаться |

## Фичи

| Issue | Кто просит | Суть |
|---|---|---|
| [#3](https://github.com/kirill0991/ai-for-developers-project-387/issues/3) | Гость, владелец | Гость не может отменить свою бронь |
| [#4](https://github.com/kirill0991/ai-for-developers-project-387/issues/4) | Владелец | Гостям предлагается время в выходные, когда владелец не работает |

## Порядок

Сначала баги (#1, #2): они небольшие и на них удобно отладить цикл «issue → агент → pull request →
ревью». Затем фичи (#3, #4): они затрагивают API-контракт (`spec/main.tsp`) и требуют решений,
которые стоит обсудить в issue до кода.

Новые задачи заводятся как issue с меткой `needs-triage` (см. `docs/agents/triage-labels.md`),
а этот файл обновляется, когда план меняется.
